# AI 生图卡片：P0 用例

更新：2026-11-04。统一入口：[全部测试用例](../../cases/README.md#ai生图p0用例)。仅编写P0参数与生成主链路用例，本轮未执行生成任务。

## 需求摘要

- 从“素材与生成 / Assets & Generation”的“AI生图 / AI Image”卡片进入，选择分辨率、图片比例后发送生成请求。
- 抽样覆盖1K、2K、4K，以及1:1、9:16、16:9、3:4、4:3；不穷举全部分辨率与比例组合。
- 覆盖默认参数、显式选参、生成下载、同会话切换比例和分辨率。最终判断以下载文件的实际像素为依据，不能只看卡片标签或助手回复。
- 沿用原IG-01～05，补充IG-06～08；旧矩阵改为链接本页，避免维护两份正文。已有默认生图脚本映射IG-05，不另算一条；CS-01为总结视频，不复用该编号。

## 测试假设与通用前置 P

1. 专用测试账号已登录预发工作台；当前无同账号并发任务，余额足够完成本例；AI生图服务可用。每例新建独立空会话S，只有切换类用例在S中连续生成两轮。
2. 不上传素材、不添加参考图、不使用@引用，避免混入图生图。使用卡片自身的默认提示词；该提示词由卡片提交，**不要用手工填写的新提示词替代卡片入口**。若当前版本显示可编辑提示词，先记录实际行为差异，再以产品明确的卡片规则执行。
3. 不改变当前生图模型；两轮切换用例也保持同一模型。记录模型/提供方、会话ID及参数选项。若当前模型不支持本例参数，记录不支持的选项及前置受阻，不静默换模型、降分辨率或换比例。
4. 本页根据工程已有登记的1K/2K/4K及默认1K、1:1编写。本轮没有重新实测参数面板，执行时须保存初始选中态、最终选中态和实际可选项。
5. 运行前取得**当前模型生效的“分辨率档位×比例→像素W/H”规格表**，记录版本及本例期望W/H。工程尚未保存该映射，不能自行假定1K/2K/4K均代表长边、短边或正方形边长。没有映射时可以执行交互与比例检查，但分辨率像素验收只能标“待确认”，不能报完整通过。

## 通用执行与验收 E

1. 每轮从卡片进入、核对参数、发送一次。运行中只显示停止按钮属于正常交互，等待终态后再进行下一轮；出现补槽则按本轮已指定的参数填写，记录问题、填写值和截图后继续。
2. 保存提交前参数截图，记录请求或执行计划中的有效分辨率/比例、关联run_id、会话ID及终态。界面标签正确但实际执行参数仍是旧值，应判未通过。
3. 本轮须done，并在本轮任务中返回一个可查看、可下载的图片交付物；文件非空、可完整解码。以文件内容识别实际图片格式，不只检查扩展名；不能把历史图片充当本轮交付物。
4. 下载图片读取实际W/H，与P.5的当前模型规格表逐项核对，取整只能按规格允许值处理。比例a:b按 `abs(W-H*a/b)≤1像素` 核对；1:1须宽高相等。不得任意放宽比例或仅根据图片标签宣称通过。
5. 切换类用例同时核对两轮有效参数、实际尺寸及对应关系；第二轮使用新参数，第一轮文件ID及下载内容仍可回读、SHA-256不变。两轮画面内容允许不同，不要求随机生成内容一致。
6. 发送完成后输入框不残留上轮已发送内容；不要求参数面板必须关闭或参数重置，此行为本轮没有明确产品规则。无需根据分辨率猜测扣费金额；缺少关联流水时只记录实际余额变化。

## 待确认事项

1. 当前生图模型在各档位和比例下的精确像素映射及允许的取整值：影响全部用例的分辨率内容验收；不得用产物自身尺寸反推期望值后再自证通过。
2. 当前版本是否仍隐藏卡片默认提示词：已有文档按隐藏提示词登记，执行前需核对；本轮未声明已在新版逐项验证。

## 未明确规则与覆盖边界

- 当前精确像素映射尚待补齐，已在P.5列为独立验收条件。不能把“请求写4K”当成“图片已达到4K档”的证据。
- 本次不新增P1/P2，也不穷举21:9、9:21等全部比例；不包含图生图、图片编辑、提示词语言/内容质量、权限、计费规则或真实服务端故障注入专项。
- 图像主体内容是否符合默认提示词需在取得实际默认提示词后对照；本表不虚构隐藏提示词，不以任意图像内容作严格的语义判定。
- 当前仍只有1条已有AI生图自动化脚本，对应IG-05的部分检查；其余7条未接脚本。本轮没有新增或执行自动化，卡片套件仍是原7条脚本，不是8条AI生图脚本。
