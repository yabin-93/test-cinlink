# 本地素材查找：P0 测试用例

更新：2026-11-04。统一入口：[全部测试用例](../../cases/README.md#本地素材查找p0用例)。17条P0中，LF-01～03已接自动化并有头实测，0通过/3未通过；LF-04～17仍PLAN/未执行。详见[本轮执行记录与失败截图](local-footage-results-20261104.md)。

## 需求摘要

- 通过“素材与生成 → 本地素材查找 / Find Local Footage”卡片，以自然语言检索当前项目已分析的视频。
- 使用指定目录的4个原视频，覆盖不同音轨条件、单镜头/多镜头、匹配与不匹配、项目隔离及同项目会话复用。
- 核对源文件、片段时间、匹配依据和预览内容；结果作为候选加入当前会话上下文，不将“任务完成”单独作为检索成功依据。
- 沿用CS-06作为卡片功能总入口，本页LF编号细化验收；与既有入口冒烟分别统计，不复用已退役CS-07～09。

## 依据与假设

1. 用户提供功能完成信息、素材路径及P0范围，未提供正式PRD；以下主链路按本地实现编写，隔离、异常及状态残留场景标明QA风险来源。
2. 本地前端 `E:\proj\cinlink-studio-web\src\app.js` 的 `runWorkspaceMaterialSearch`、`workspaceAnalyzedLibraryScopeFor` 与 `workspaceMaterialSearchReply` 显示：搜索当前项目已分析素材、区分无结果与请求失败、保留匹配时间和依据、将候选暂存到输入上下文。`src/lib/material-search-presentation.js` 及其测试提供结果持久化/去重依据。**这是本地源码依据，不代表本轮已实测预发。**
3. 搜索可使用专用检索请求和本地任务记录，不一定创建常规Agent run或生成新视频。本地API实现为 `POST /v1/library/material-search`；执行时记录实际版本与请求，不将旧run接口强加为验收条件。
4. 初稿仅本地素材核验；其后按用户限定范围接入LF-01～03并执行。当前预发通过Agent的 `search_materials`（segment/project）返回匹配短片，来源和区间位于 `facts.source_file_id/source_file_name/start_ms/end_ms`；本地旧源码的专用检索接口不作为本轮强制契约。其余14条未执行，不将这3条结果迁移为其他用例通过。

## 通用前置 P：必须完成的准备

1. 使用专用测试账号登录预发工作台，记录环境/版本、账号范围；余额足够支付媒体分析。单个浏览器串行操作，无同账号并发任务。不要假设检索或分析免费，也不预设具体扣费金额。
2. 按本例素材集合新建专用项目：在“创建项目 → 上传项目 / Upload project”选择所需夹具文件夹。全量项目P4直接选上述“素材查找”目录；P1/P2/P3分别仅放F1/F2/F3；P123仅放F1～F3。自动化也可从本轮刚上传的P4向新建单素材项目关联对应真实文件ID，回读验证集合精确为1个文件、下载哈希与原片相同，不重复上传。记录项目ID及文件ID、原名、大小和时长，等待同步完成并逐项核对。**聊天附件上传完成不能代替项目素材同步完成。**
3. 在该项目内新建会话S，进入“素材与生成 → 本地素材查找”；稳定锚点参考 `[data-workspace-action-id="local-material"]`。本专项直接查询项目素材库，不依赖@候选，不通过重复上传或@登记改变检索范围。
4. 除LF-01外，在查询前点击“立即分析 / Analyze”并核对分析确认页包含本例素材，确认分析费用后继续；等待逐文件分析成功。P4须4/4、P123须3/3、单文件项目须1/1。记录失败项；未就绪不能把后续无结果直接判为检索无匹配。已有有效分析缓存可直接就绪，不强求重新分析或重复扣费。
5. 各例使用独立会话或按本例说明复用；查询前清理本例不需要的已选候选，避免历史上下文干扰。LF-12同项目双会话不重传、不重新分析；LF-13保留前轮历史以检查连续查询。
6. 若预发入口/计数形式与本地源码不同，保存实际页面及版本，核对是否具备等效操作；无法完成项目同步或分析时记前置阻塞。运行中出现补槽，按本例已指定目标填写、取证并继续，不将“未要求澄清”当作停跑理由。

## 通用执行与验收 E

1. 每轮点卡片进入搜索模式，输入本例完整提示词，发送一次并等待终态；记录查询原文、当前项目/会话ID、请求/任务标识（若有）、响应状态、候选源文件ID/名称、时间和匹配依据。检索没有run_id时注明“不适用”，不能编造或用历史run代替。
2. 正向用例必须返回与本轮目标匹配的真实源素材；打开候选预览，按匹配时间定位并核对源画面，不能只凭助手说“找到”或任务done判通过。结果应有可核验的片段时间/匹配依据；若UI不展示全部字段，结合本轮响应取证，同时记录显示缺口。
3. 每个返回时间段满足 `0 ≤ start < end ≤ 源片时长`。F4目标段须与参照片段有正时长交集且预览包含目标；整段300秒作为唯一“精确片段”不能完成定位验收。不擅自规定精确到帧、固定15秒长度或未获确认的容差；边界相交本身也不足以证明内容正确。
4. 当前查询结果和历史消息、手动选择的上下文分别核对。连续查询可保留旧会话历史，不要求自动删除用户已选素材；**本轮结果的时间/依据必须对应本轮查询**。同一源文件可只返回一个最佳片段，不要求同一视频出现20张卡或一次展示所有镜头。
5. 搜索交付可以是原素材线索或新生成的命中短片。本轮预发实际返回MP4短片，短片文件ID与原片ID不同属于正常情况，须按facts追溯来源、校验区间并播放实际内容。不将自动打开编辑器或插入时间线作为既定行为；不提交额外编辑任务。候选暂存/继续引用的旧源码行为需对新版另验，不由本次LF-01～03证明。
6. 保存分析就绪截图、查询原文、匹配结果及源片目标帧；失败保存实际失败页和对应响应。敏感链接脱敏。明确区分“无匹配”“请求失败”“素材未分析”和“前置阻塞”；不能用空列表吞掉服务异常。

## 待确认事项

- 当前部署的结果交互、时间展示精度，以及是否支持一源多片段分页：按实测登记；本页不预设固定排序、召回率、返回条数上限或延迟SLA。
- 片段直接加入时间线、按命中区间裁切的产品交互尚未确认；本页验收到候选预览和上下文可复用，后续编辑另列用例。
- 当前文件的完整语音逐字稿和画面文字金标尚未提供；LF-17提供独立ASR语音线索并要求先听审，视觉用例不冒充语音或OCR检索通过。

## 覆盖策略

P0聚焦“素材可被分析 → 查询找到正确源片和位置 → 候选可用”，以及可能造成误用素材的项目隔离、会话复用和查询残留；使用既有素材区分音轨有无，不穷举所有格式/语言/浏览器。
