## 二、多工作流场景

| 编号 | 场景 | 示例指令 / 操作 | 关注点 |
|---|---|---|---|
| MW-01 | 串行依赖（先剪后字幕） | 先「长变短」→ 再对产物「生成中文字幕」 | 第二条任务是否引用第一条产物、时长是否继承 |
| MW-02 | 同源并行（字幕 + 翻译） | `给这个视频生成中文字幕` + `翻译成英文` | 两条任务是否共用素材、产物是否串台 |
| MW-03 | 同源并行（增强 + 文字水印） | `增强画质` + `加文字水印 E2E-TEST` | 产物是否叠加、是否互相覆盖 |
| MW-04 | 单句复合意图 | `增强画质并加中文字幕` | 一个 prompt 是否拆成多个子任务、产物是否齐全 |
| MW-05 | 多素材多任务 | 视频 A 生成字幕、视频 B 翻译 | 素材与任务是否一一对应、互不串台 |
| MW-06 | 一句话 3 工作流（字幕+翻译+总结） | `给这个视频生成中文字幕，翻译成英文，并总结要点` | run=3；产物=中/英 SRT+总结；顺序=字幕→翻译→总结；每步引用上一步 |
| MW-07 | 一句话 4 工作流（去口水词+字幕+翻译+导出） | `去掉口水词，加中文字幕，翻译成英文，并导出字幕文件` | run=4；产物=清理视频+中/英 SRT+导出文件；导出语言=英文；时长与清理视频一致 |
| MW-08 | 一句话 5 工作流（长变短+字幕+翻译+水印+导出） | `剪成 30 秒高光，加中文字幕并翻译英文，再加文字水印，最后导出成片` | run=5；产物=30 秒视频+中/英 SRT+带水印成片+导出；成片 30±2 秒且含字幕/水印 |
| MW-09 | 一句话 6 工作流（混剪+字幕+翻译+增强+水印+导出） | `把两个视频混剪成 18 秒，加字幕并翻译，增强画质，加水印后导出` | run=6；混剪失败时后续不执行；报告失败步骤；已成功产物可下载；不重复计费 |
| MW-10 | 显式顺序（增强→字幕→长变短） | `先增强画质，再加中文字幕，最后剪成 20 秒` | run=3；创建顺序=增强→字幕→长变短；最终 20±2 秒且含字幕 |
| MW-11 | 生成→字幕→翻译依赖链 | 卡片生成视频 → `给这个视频加中文字幕` → `翻译成英文` | run=3；后两步 source=生成视频 ID，不是原素材；SRT 时间轴匹配生成视频 |
| MW-12 | 中间步骤失败 | `加中文字幕、翻译成英文、导出成片`，翻译失败 | run=3；字幕成功、翻译失败、导出未执行；报告 1 成功 1 失败 |
| MW-13 | 参数冲突 | `剪成 20 秒，再剪成 30 秒` | 只产生 1 个版本或触发澄清；不出现 20 秒与 30 秒两个版本 |
| MW-14 | 8+ 工作流长链路 | 总结+字幕+翻译+长变短+增强+水印+导出+生成解说 | 8 步全部有结果或明确拒绝；超上限返回错误；不静默丢步骤 |
| MW-15 | 双视频分别字幕 | 视频 A `加中文字幕`、视频 B `加英文字幕` | run=2；SRT×2 各绑定对应视频 source；A 中文、B 英文；不串 |
| MW-16 | 双视频分别翻译 | 视频 A `翻译成英文`、视频 B `翻译成日文` | run=2；A 英文、B 日文；产物 source 对应；不互换 |
| MW-17 | 三视频混剪+字幕+翻译 | 3 个视频混剪成 30 秒 → 加字幕 → 翻译 | 引用 3 个 cloud_file_id；成片 30±2 秒；字幕覆盖全片；翻译语言正确 |
| MW-18 | 视频+图片水印+字幕 | 视频加图片水印，同时生成中文字幕 | run=2；水印图只作 watermark 引用；视频含图片水印；SRT 时间轴对应视频；图片不被当视频 |
| MW-19 | 视频+音频配音 | 视频 + 音频素材，生成旁白/配音并合成 | 引用视频+音频；音频作旁白/配音输入；成片有音轨；不把音频当画面 |
| MW-20 | 多素材歧义 | 两个视频不 `@`，说“给这个视频加字幕” | 两视频不 @：澄清或明确选择；不静默选错；产物 source 可核对 |
| MW-21 | 跨会话素材复用 | 会话 A 上传素材，会话 B 引用同一素材 | A 上传后 B 的可见性符合项目规则；引用成功时产物归属 B；不串其他项目 |
| MW-22 | 多素材部分失败 | 视频 A 字幕成功、视频 B 翻译失败 | A 产物可下载；B 失败可见；A 不回滚；汇总=1 成功 1 失败 |

> 多工作流只保留 **S1 提示词**：多工作流的核心是上下文与顺序，S2 连续点卡片已由单工作流 S2 + 卡片用例覆盖，不再乘 S2。

## 三、素材进入方式（M）

| 编号 | 方式 | 做法 |
|---|---|---|
| M1 | 对话框直接上传 | 点「＋」上传视频，不 `@`，直接发送 |
| M2 | 首页项目对话框 @ | 新建项目对话框上传视频，在对话框中 `@` 选中后发送 |
| M3 | 上传后再 @ | 先「＋」上传，再在输入框 `@` 选中后发送 |

## 四、任务发送方式（S）

| 编号 | 方式 | 做法 |
|---|---|---|
| S1 | 直接发送提示词 | 输入框输入指令并发送 |
| S2 | 点击功能卡片 | 卡片分两类：<br>• **S2-a 隐藏提示词**：AI 生图/AI 视频，点卡片后直接提交，前端不展示提示词；<br>• **S2-b 预填提示词**：长变短等剪辑卡片，会把默认提示词写进输入框，并展示参数（如精华时长），需用户确认发送。 |

> S2 说明：不同分组的卡片行为不同。\n> • 「素材与生成」的 AI 生图/AI 视频：隐藏提示词，参数（分辨率/比例/时长）可见；\n> • 「剪辑与优化」的长变短：会把默认提示词写进输入框，并出现「精华时长」参数；\n> 断言时要先确认卡片属于哪一类，不能统一用“输入框为空”或“输入框有文本”。\n> 因此 S2 不能用“输入框文本”做断言，只能看 run 是否创建、路由/产物是否是该卡片的工作流。\n> 一张卡片只承载一个工作流。连续点两张时，第二张的结果卡片会替换第一张；
> 多工作流不使用 S2；单工作流 S2 的连续点击行为见卡片用例。

## 八、自动化落地

```ts
const single = [...];   // 8 个工作流
const multi = [...];    // 5 个多工作流场景
const materials = ["M1", "M2", "M3"];
const sends = ["S1", "S2"];

for (const flow of [...single, ...multi])
  for (const m of materials)
    for (const s of sends)
      test(`${flow.id}-${m}-${s}`, async ({ page }) => {
        await enterMaterial(page, m, flow.assets);
        await sendTask(page, s, flow.steps);
        await assertRuns(page, flow);
      });
```

`assertRuns` 需要支持多 run：等全部收敛、汇总产物、检查隔离。

## 十、AI 生图卡片（带参数的 S2）

首页「素材与生成」分组里有 AI 生图、AI 视频等卡片；点击 **AI 生图** 后需要先选：

- 分辨率：`1K` / `2K` / `4K`
- 图片比例：`1:1` / `3:4` / `4:3` / `9:16` / `16:9` / `21:9` / `9:21`

### 参数用例

| 编号 | 分辨率 | 比例 | 断言 |
|---|---|---|---|
| IG-01 | 1K | 1:1 | 产物为正方形；边长符合 1K 档 |
| IG-02 | 2K | 9:16 | 产物竖屏；宽高比 ≈ 9:16 |
| IG-03 | 4K | 16:9 | 产物横屏；分辨率达到 4K 档 |
| IG-04 | 2K | 3:4 | 切换比例后重新生成，产物比例随之变化 |
| IG-05 | 默认 | 默认 | 未手动选择时使用默认参数，且参数面板有默认选中态 |

### 断言要点

- 产物实际像素尺寸与所选分辨率档位一致（允许平台侧取整）；
- 宽高比与所选比例一致（允许 ±1px）；
- 切换比例后再次生成，不复用上一次尺寸；
- 参数选择面板在发送前可见、可切换，发送后不残留提示词。

### S2 通用步骤（带参数卡片）

1. 点卡片（AI 生图）；
2. 在参数面板选择分辨率与比例；
3. 点发送；
4. 等待 run 完成，下载产物；
5. 校验像素尺寸与宽高比。
## 十一、AI 视频卡片（带参数的 S2）

首页「素材与生成」分组里的 **AI 视频** 卡片，发送前需要选：

- 分辨率：`720P` / `1080P`
- 视频比例：`16:9` / `9:16` / `1:1`
- 生成时长：`5 秒` / `10 秒`

选完后点发送，提示词由卡片默认生成、前端不展示。

### 参数用例

| 编号 | 分辨率 | 比例 | 时长 | 断言 |
|---|---|---|---|---|
| IV-01 | 720P | 16:9 | 5 秒 | 横屏、720P 档、时长 5±0.5 秒 |
| IV-02 | 1080P | 9:16 | 10 秒 | 竖屏、1080P 档、时长 10±1 秒 |
| IV-03 | 720P | 1:1 | 5 秒 | 正方形、时长 5±0.5 秒 |
| IV-04 | 1080P | 16:9 | 5→10 秒 | 切换时长后重新生成，产物时长随之变化 |
| IV-05 | 默认 | 默认 | 默认 | 不手动改参数时使用默认档，面板有默认选中态 |

### 断言要点

- 产物分辨率与所选档位一致（允许平台取整）；
- 宽高比与所选比例一致；
- 实际时长与所选时长一致（±1 秒）；
- 切换时长后再次生成，不复用上一次时长；
- 参数面板在发送前可见、可切换，发送后不残留提示词。
## 十二、长变短卡片（S2-b：预填提示词 + 精华时长）

「剪辑与优化」分组里的卡片（去口水词、画面增强、长变短、添加水印）点击后表现不同，其中**长变短**已确认：

- 会把默认提示词写进输入框：`把这条长视频剪成适合发布的短视频`
- 出现参数「精华时长」，默认 `3 分钟`
- 用户可改时长后点发送

### 参数用例

| 编号 | 精华时长 | 断言 |
|---|---|---|
| LT-01 | 3 分钟（默认） | 输入框出现默认提示词；产物时长 ≤ 3 分钟 |
| LT-02 | 1 分钟 | 产物时长 ≈ 1 分钟（±10 秒） |
| LT-03 | 5 分钟 | 产物时长 ≈ 5 分钟（±30 秒） |
| LT-04 | 3 分钟 → 1 分钟 | 切换后重新生成，产物时长随之变化 |

### 断言要点

- 点击卡片后输入框应出现默认提示词（区别于 AI 生图/视频的隐藏提示词）；
- 精华时长选择器有默认值，切换后再次生成应使用新值；
- 产物时长与所选精华时长一致（允许平台裁剪误差）；
- 发送后输入框被清空，参数面板关闭。

## 十八、链路用例（跨工作流，`[PLAN]`）

单工作流验证“能不能跑”，链路验证“产物能不能被下游继续消费”。

| 编号 | 链路 | 关键断言 | 状态 |
|---|---|---|---|
| CHAIN-01 | 长变短 → 加字幕 | 第二条引用短视频；字幕时长 ≤ 短视频时长 | `[PLAN]` |
| CHAIN-02 | 长变短 → 字幕 → 翻译 | 三级产物逐级引用；目标语言正确 | `[PLAN]` |
| CHAIN-03 | 去口水词 → 加字幕 | 清理后字幕与清理后视频对齐 | `[PLAN]` |
| CHAIN-04 | 混剪 → 加字幕 | 混剪产物可继续处理；字幕覆盖全片 | `[PLAN]`（受 MIX-001 影响） |
| CHAIN-05 | AI 生视频 → 加字幕 | 生成内容可被下游消费 | `[PLAN]` |
| CHAIN-06 | AI 生视频 → 加水印 → 导出 | 生成后编辑链完整；导出可下载 | `[PLAN]` |
| CHAIN-07 | AI 生图 → 图片编辑 → 导出 | 图片链路闭环；尺寸不被意外改变 | `[PLAN]` |
| CHAIN-08 | 查找片段 → 引用 → 长变短 | 片段级输入；只处理选中片段 | `[PLAN]` |
| CHAIN-09 | 历史产物 → 再次加工 | 产物可复用；不重复上传原片 | `[PLAN]` |
| CHAIN-10 | 生成失败 → 重试 | 失败可见；重试复用原参数 | `[PLAN]` |
| CHAIN-11 | 额度不足 → 发起生成 | 明确提示与阻断；不产生半成品 | `[PLAN]` |
| CHAIN-12 | 提示词发起 AI 生图/视频 | 与卡片入口同路由、同参数默认值 | `[PLAN]` |

### 链路断言原则

1. **引用正确**：下游必须引用上游产物，而不是原素材；
2. **参数继承**：分辨率/比例/时长/语言在链路中不被重置；
3. **产物可追溯**：每个产物能对应到发起它的 run；
4. **不重复计费**：复用历史产物不重复上传/预扣；
5. **失败可恢复**：中间任一步失败，能从该步重试，不从头再来。

> 执行顺序建议：CHAIN-05/06/07（生成→编辑→导出）→ CHAIN-01/03（传统串联）→ CHAIN-10/11（异常与额度）。
