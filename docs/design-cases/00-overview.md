## 怎么用

- Markdown：按模块评审、补充、进仓；一页一个文件。
- Excel：`reports/design-cases.xlsx`，所有用例汇总在一张表，可直接导入用例平台。
- 用例编号：`DC-<模块>-<序号>`；优先级 P0（主流程/阻塞）、P1（关键分支）、P2（体验/边界）。

## 约定

- **前置条件**里的“测试账号”沿用现有预发账号；涉及支付的用例需使用沙箱/测试卡。
- **操作步骤**用 `→` 分隔连续动作；`<br>` 在 Excel 中转为换行。
- **预期结果**严格区分“设计稿明确写出”与“按现有产品行为推断”，后者在备注中标注“待确认”。
- 标注 `可自动化` 的用例，指可接入现有 Playwright 工程（`tests/staging/`）或用例化 UI 断言；其余为人工/半自动。

## 已知限制

- 设计稿是静态稿，个别交互（如拖拽排序、支付回调）没有逐帧稿，预期结果按标注与现有产品行为整理，标了“待确认”。
- 页面“分析 / 历史记录 / 走查画布”是对内文档页，未纳入功能用例。
- 导出画板保留在 `reports/figma-exports/`，可直接对照截图评审。

- 需求用例必须写清前置条件、操作步骤、预期结果；用 `npm run cases:check` 校验（空字段、短字段、重号、非法优先级）。
