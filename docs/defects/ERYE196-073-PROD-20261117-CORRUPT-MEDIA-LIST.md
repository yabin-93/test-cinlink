# 【ERYE196-073】损坏MP4上传被拒绝后，刷新导致整个项目媒体列表无法加载

云效：[FWXC-637](https://devops.aliyun.com/projex/project/1e401ac99539c3999e00e40006/bug#openWorkitemIdentifier=ce00f069fc5d3bd61d41ade36f)，官方OpenAPI回读核验通过。

**现象**

损坏文件被提示拒绝，但刷新后整个媒体列表无法加载；元数据批量读取持续报损坏字节错误。

**前置步骤**

1. Chrome登录生产环境，打开已有正常视频素材和时间线的测试项目。
2. 准备66字节无有效媒体数据的E196-corrupt-073-20261117.mp4；精确测试字节见核验附件。

**提示词**

无Agent提示词，使用编辑器媒体面板的实际导入入口。

**复现步骤**

1. 在媒体面板导入该损坏MP4，观察拒绝提示。
2. 正常刷新并重开原会话的视频编辑器，打开媒体→工程列表。
3. 核对原有正常素材是否仍可浏览，以及媒体列表/元数据读取结果。

**实际结果**

首次提示“Media type could not be verified from the uploaded bytes.”，无完成素材卡且时间线未变。刷新后整个媒体面板显示“无法加载媒体/重试”，原有正常素材也未显示。真实editor/media仍返回素材标识，后续files/metadata反复返回file_service_unavailable及相同损坏字节提示。
会话a9a99d8f-02fa-4889-9bb9-30a752a925a2；项目25738b66-451d-4c5a-996d-a66a9f926460。

**预期结果**

明确拒绝损坏文件并提供恢复方式；错误应局限于该文件，正常素材列表仍可加载和使用。

**影响**

一次损坏文件导入后，用户无法继续从该项目媒体面板选择原有合法素材。
