# 【ERYE196-067】站点存储配额受限时在线字幕修改被阻断

云效：[FWXC-622](https://devops.aliyun.com/projex/project/1e401ac99539c3999e00e40006/bug#openWorkitemIdentifier=c9a8ac2ea07617dec2de679b0d)；官方OpenAPI正文、字段及附件回读通过。

**现象**

站点存储配额受限时，在线手动修改字幕后编辑器进入只读并提示未保存，另一标签页仍读取旧字幕。

**前置步骤**

1. Chrome 登录生产环境测试账号 U1，打开含原文字幕C1“066跨浏览器已保存”（4～6秒）的已有工程。
2. 网络保持在线；DevTools Application → Storage 可设置自定义站点配额。

**提示词**

无Agent提示词；手动将C1输入为“067在线保存”。

**复现步骤**

1. 将站点自定义配额设置为1MB；确认页面显示实际约2613MB已用、总配额1.0MB（custom）。不清除站点数据。
2. 在线手动把C1改为“067在线保存”，按Return确认。
3. 观察编辑器状态，并在另一独立标签页刷新同一会话，核对服务端可见字幕。

**实际结果**

当前页进入只读，黄色提示“未保存的内容仍保留在此页面。”，提供重试原操作、导出修改、加载服务器版本等恢复入口。独立标签页刷新仍为“066跨浏览器已保存”，本次在线修改没有完成保存。
会话：a9a99d8f-02fa-4889-9bb9-30a752a925a2。

**预期结果**

本地草稿缓存无法写入时，应清楚提示缓存受限，并允许网络正常的编辑按既有在线保存机制完成；不应仅因本地配额限制阻断在线编辑。

**影响**

本机存储不足的用户即使网络正常，也无法完成字幕在线修改。

**补充**

同步标识：ERYE196-067-PROD-20261116-QUOTA-ONLINE

实测生效配额为1MB，0MB输入未生效，不作为证据。未清Cookie、缓存或站点数据；结束时取消自定义配额恢复默认约147064MB，并放弃本次自有未保存修改以恢复服务器版本。不推断后台事务失败或数据损坏；后续离线草稿分支未执行。已查云效425条缺陷，与FWXC-280的429鉴权恢复场景不同。
