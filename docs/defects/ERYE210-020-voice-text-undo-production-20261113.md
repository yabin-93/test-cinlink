# 【生产环境】【ERYE210-020】配音文案修改后撤销未恢复原稿，刷新重开仍显示新稿

云效：[FWXC-507](https://devops.aliyun.com/projex/project/1e401ac99539c3999e00e40006/bug#openWorkitemIdentifier=4861ae7970e41e1293c07e3612)；2026-11-13通过官方OpenAPI直接新建，不做历史去重。状态🤔AI提缺陷，负责人牛诗晴，重构10-29，生产环境，优先级中、严重程度3-一般。

前置各三条，详细复现及验证边界单列。3张真实截图已上传并嵌入，连同原片、供回归准备的中文SRT及核验JSON共6附件；正文、字段、附件ID/名称/字节数及图片引用回读通过。用例ERYE210-020保持Failed。[本轮执行报告](../cases/requirements/ERYE-210/results-016-020-prod-20261113.md#erye210-020)。

**现象**

第1句配音文案从“欢迎使用 CinLink。”修改为“新稿未提交”后，切换模块和收起重开都保留了新稿；点击一次撤销并等待后仍为新稿，整页刷新重开也没有恢复原稿。

**前置步骤**

1. Windows / Google Chrome登录生产环境https://app.cinlink.ai，账号具有工程编辑权限。
2. 新建专用测试项目及独立会话/工程，准备20秒原片、两句已保存中文配音稿及两段旧配音音频：第1句“欢迎使用 CinLink。”，第2句“这是导航测试。”。
3. 等本工程自己的文稿准备并保存，刷新重开确认原稿正确、旧音频可用，且没有其他编辑或生成任务。

**提示词**

无Agent提示词；通过Voiceover文案输入框、模块切换及全局撤销操作，无补槽、无生成任务。

第1句完整原稿：`欢迎使用 CinLink。`
第1句完整新稿：`新稿未提交`
第2句保持：`这是导航测试。`

**复现步骤**

1. 在新工程打开Voiceover/配音，确认第1句配音文案为“欢迎使用 CinLink。”，第2句为“这是导航测试。”。
2. 在第1句配音文案框中全选并输入`新稿未提交`，暂不生成声音。
3. 点击Captions/字幕，再回Voiceover/配音，确认第1句仍为`新稿未提交`。
4. 按当前页面离开文本框保存的方式结束编辑（本次按Ctrl+Enter后失焦），收起编辑区并重开同一工程，再进Voiceover；确认新稿仍保留。
5. 点击时间线工具栏全局“撤销”一次，等待约20秒至文本框恢复可操作，检查第1句配音文案；本次仍为`新稿未提交`。
6. 刷新整页，重开同一工程并进入Voiceover；本次仍为`新稿未提交`，未恢复为“欢迎使用 CinLink。”。
7. 对照第2句及两段旧音频，确认没有自动生成新声音或清空原声音。

**实际结果**

新文案切页、收起重开均保留，但撤销一次未恢复原稿，等待20秒及随后刷新重开仍显示`新稿未提交`。最终保存核验版本5，第2句保持，两段旧音频仍ready；本次生成任务提交数0。

结果依据真实配音文案框及刷新重开显示判定。不能以保存结构中旧音频关联文本仍为原文，替代用户实际看到的可编辑文案结果。

**预期结果**

文案切页时不静默丢稿、不自动生成声音，保存重开保持一致；点击一次撤销应恢复该次文案修改前的“欢迎使用 CinLink。”，刷新重开也应一致，第2句和原音频不受影响。

**影响**

配音文案的撤销无法恢复用户上一版内容，用户容易误认为已恢复；必须手动找回原文并重新修改，降低编辑可靠性。
