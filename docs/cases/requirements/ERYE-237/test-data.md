# ERYE-237 测试前置操作与数据

更新：2026-11-05。配合[本版重新编写的用例](cases.md)。下面是**待准备的基线和夹具规格**，本轮没有上传素材、建立真实工程、调用图像模型或注入故障。别名不是现有服务端ID，执行时必须解析为真实身份。

## 通用前置 P

1. 提测方提供实际Web/macOS版本、API/worker/provider adapter版本、能力开关、发布schema和专用账号；记录平台、浏览器、DPR、测试批次。Web为本工程主要执行端，macOS使用同数据另记入口结果；没有macOS环境不能宣称跨端通过。
2. U1是测试图片/文档所有者；U2是没有U1资源权限的独立账号。仅在专用测试空间准备撤权、取消和故障数据。真实生成可能计费，执行前具备本批额度与授权；本次设计工作不执行这些动作。
3. 读取 `editor_get_capabilities` 和上下文，保存schema、operation、参数范围、输入/输出限制、费用要求、executor及不可用原因。operation名称来自PRD拟新增契约，不表示当前版本已实现；实际路由可不同，领域语义须相同。
4. 对照PRD默认和用户确认：批注最多10条；单条正文2000、全局4000、合计12000、标签80；画笔/橡皮直径1～256源像素、字号8～512、RGB 0～255；输入JPEG/PNG/WebP，默认20MB/24MP。schema收紧需有公布依据；与已确认需求不一致要记录差异，不能根据服务返回的错误配置自证通过。
5. 每条用例从独立、已验证基线开始。记录conversationId、documentId、assetId、versionId、revisionToken、authority、draftId和原文件SHA；副本产生新ID必须重新登记。进入测试用例前验证前置的文字、对象、蒙版、版本和阶段，不借另一例未确认的结果。
6. 表中I1/I2/I3、V1/V2、T1、Q、J等均为本文登记别名。Agent提示词发送前替换为本例真实名称/稳定ID和确定参数；“第2张”等指代专测保留其自然表达，并独立记录正确答案。不得把示例ID或未替换的别名直接发送到真实服务。
7. 按本例完整指令一次发送；先等终态再执行依赖动作。合法补槽/计划确认按本例参数填写并继续，保存问题、填写值和截图。专测澄清时先验证答复前没有写入，再选择指定候选继续；回答不计为新设计用例。
8. 只看到权威持久化确认才能记保存；分开记录技术任务结果、实际文件、语义复核及费用。已受理任务按command/submission/job回读；取证网络错误不能用新任务或别例产物补齐。
9. 源图及已完成版本不可变。比较时同时看UI、领域响应、权威快照、文件内容、历史与账务；随机生成图不要求两次hash相同，确定性绘制在相同规范快照/渲染条件下比对。

## 双入口配对规则

- 用例同时要求UI和Agent时，准备两个独立但内容/对象/版本血缘相同的基线，重新绑定各自ID；不要先UI修改，再让Agent在已经改变的同一基线上“重复”执行。
- UI路径按按钮/浮层操作；Agent路径用表中提示词和[分析页操作矩阵](analysis.md#ui与agent操作测试点)的同参数自然语言调用。缺少单独提示词的UI分支，由该操作矩阵提供等价指令；目标和数值必须与UI一致。
- 比较operation语义、sourceVersion/快照、实际参数、revision变化、historyGroup、输出约束、错误及费用类型；视图请求比较view状态，不能据此要求内容revision变化。
- 一个设计用例可以有多组边界数据及两个入口结果，统计仍为一个ID。任一必测入口未实现/未测，不能给整例完整通过。内置Agent路径必须有真实领域调用，模拟点击和仅文字回复不算。

## TD-GEOMETRY与TD-RATIO

BG源1001×1000；Q=(0.25,0.25)，按点中心公式得到(250,250)。R=(x=0.1,y=0.2,w=0.2,h=0.1)，矩形像素边界向外取整为left=100/top=200/right=301/bottom=300（右/下为边界，不是最后像素索引）。使用有理数或明确精度的独立计算，避免浮点误差伪造额外像素。

点：`round(x×(W−1)), round(y×(H−1))`；圆半径以短边为单位，示例0.05×1000=50源像素，不在非方图横纵归一坐标里画同半径椭圆。非法样本：NaN、Infinity、-0.01、1.01、零面积、越界矩形、源版本不符/尺寸不符/sha错误的mask。mask协议0保留、1编辑，抗锯齿为[0,1]；provider的相反约定只能由adapter转换。

默认扩图 `k=ceil(max(W/a,H/b))`；画布(a×k,b×k)，默认居中，奇数多1像素放右/下。1001×1000独立标准如下：

| 比例 | k | 期望W×H | 左/右留白 | 上/下留白 |
|---|---|---|---|---|
| 9:16 | 112 | 1008×1792 | 3/4 | 396/396 |
| 3:4 | 334 | 1002×1336 | 0/1 | 168/168 |
| 1:1 | 1001 | 1001×1001 | 0/0 | 0/1 |
| 4:3 | 334 | 1336×1002 | 167/168 | 1/1 |
| 16:9 | 112 | 1792×1008 | 395/396 | 4/4 |

该表只适用于默认居中、完整保持主体、能力未超限的条件；指定主体锚点则检查已解析位置。不能用实际输出尺寸反推期望，再宣称比例/像素通过。

## TD-TEXT与数量边界

- 批注条数9/10/11；标签79/80/81；单条正文1999/2000/2001；全局3999/4000/4001。基础边界使用BMP汉字“测”重复N次，Unicode/UTF-16/字素计数在此一致，且每份字段保存完整原值/hash。
- 合计11999：4条正文共7999字（2000+2000+2000+1999）＋全局4000；合计12000：4×2000＋4000；合计12001：4×2000＋第5条1字＋4000。每条及条数均合法，专门触发合计限制。
- 空白、Emoji、组合字符、换行和标签超限UI策略需依据冻结计数/输入规则补充断言；不将聊天输入框的视觉计数当协议。PRD没有规定输入法组合过程必须如何处理，不自行增加硬阈值。
- 图片20张：同一新会话19张独立成功生成完成图，先第20张再第21张。只测明确设计注释，导入图/派生版本/失败任务/取消的计数策略待确认。**此20张不改变用户确认的批注10条上限。**

## J-*与F-*故障前置

任务数据：J-queued（provider尚未调用）、J-running/J-provider-running（有真实执行记录）。错过短暂阶段就记未覆盖，不反复提交计费任务凑窗口。

F-*必须由提测方提供现成的**隔离靶场控制或可审计服务契约测试夹具**；本次不实施、不修改云端代码。无法定向控制本例时，记录前置受阻，不故障共享服务。浏览器响应模拟只能验证UI，不计服务端事务、取消或费用规则通过。

| 夹具 | 必须能定向产生的状态 |
|---|---|
| F-candidate-delay / F-candidate-fail | 延迟/失败本例对象识别响应，不覆盖已输入正文 |
| F-mask / F-provider-mask | 已知规范蒙版及真实adapter/provider极性与请求记录 |
| F-capability | 本例operation不可用且返回结构化原因，不伪称未上线功能已开放 |
| F-two-clients / F-pointer-hold | 两个授权客户端同读R0；真实半笔手势可保持和释放 |
| F-persist-delay / F-revision-conflict | 权威持久化等待/失败；合法测试控制制造冻结后修订冲突，不直改生产数据库 |
| F-events / F-response-drop | 原事件重复/延迟/缺口；未接收失败与已接收丢响应分别可查证 |
| F-outbox | 隔离worker在事务提交前/后中断并按原身份恢复 |
| F-preparing / F-provider-fail / F-provider-unknown | 准备失败、provider确定失败、已调用但结果未知三种阶段分别可见 |
| F-invalid-output / F-persist-fail / F-notification-fail | 硬约束错误候选、有效候选保存失败、文件已保存后的缩略图或通知失败，不能混成一次重生成 |
