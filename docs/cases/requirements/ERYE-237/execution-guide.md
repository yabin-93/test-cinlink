## 最小公共准备

1. 复用专用测试项目，可在其中建多个会话；不要求每例新建项目。每例确认无在途任务，回到已登记源版并清理本例未发引用/草稿；保留全部完成历史。UI和Agent从等价独立草稿开始，不接着上一分支修改后的图重做。
2. 上传图先处理一次才创建图片工程；提示词生图自动创建工程。优先复用已验证工程，准备消耗单列。仅上传成功不等于满足工程前置。
3. 记录实际环境、图片名称、源尺寸、目标位置和允许修改范围；其他复杂素材只在相应用例准备。普通UI不强制B0全套数据或内部ID。
4. 主步骤只执行本行；收起、缩放、换工具不等于撤销。不得把历史查看当内容撤销。画布和任务需等实际状态稳定后取证。

## 参数行与依赖

形状六类、缩放六档、比例五值、字符上下边界、两种来源、保存/未保存等是参数矩阵；每个值单列记录，可单独重跑，不能一值通过代替全矩阵。图片任务一旦受理先等待/查询，零重试；操作若直接产生任务，停止后续意图切换，未测参数保留Not Run。运行中取样错过终态仅该观察项未覆盖，不为采样反复生成。

033使用实际标注入口；042删除使用浮层右上角垃圾桶；041只移引用走输入框引用入口，不要求空框退格。文字输入先确认焦点与完整值；改旧对象样式需实际应用到所选内容。保存擦除区域等保存完成再发；圆形光标不是mask。平移有需求，但手势未知时不硬套空格拖动；mask逐笔撤销粒度未确认不作为失败标准。

## 结果怎么记

每行记录：`原ID / 分支 / 参数值 / 用例版本 / 状态 / 实际结果 / 证据链接 / 缺陷链接`。

- Passed：此分支该参数全部业务断言实际完成。
- Failed：前置满足后真实行为不符合要求；关联原缺陷，不因重整关闭缺陷。
- Blocked：该分支或参数缺前置、权限、夹具、已批准规则等，并写明缺什么；其他分支继续。
- Not Run：尚未尝试；仅查看旧证据不算新执行。

默认请求“执行018”时先跑主UI分支，另列Agent和Technical待执行；明确“完整验收018”才含全部必测分支。整体验收必须汇总所有分支及参数，存在Not Run/Blocked不能称该需求已覆盖通过。技术结果不能因为没有日志就编造成零调用或零费用。
