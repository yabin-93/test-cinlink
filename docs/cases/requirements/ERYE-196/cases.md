# 编辑器能力接入 Web 测试用例 ERYE-196

**用例范围：** 当前ERYE196-001～165，既有编号、优先级及需求来源保留。每条按标题、前置、编号步骤和预期执行；固定脚本实现单独登记。

## 共用执行规则

1. 登录本轮指定环境，使用获准测试账号和本例独立保存稿，只准备条目要求的素材/对象。记录工程、会话和修改前原稿；不沿用上一例已修改结果。
2. 工程A/PA、工程B/PB、字幕C1/C2、音轨等为本例角色，执行前按真实工程名、原文和时间一一登记。提示词占位符替换成对应实际值；明确固定的时长、数值和命中边界不得随意替换。完整数据规格见[前置与数据](test-data.md)。
3. 每轮完整指令只发送一次，等待回复结束和实际结果再继续；真实澄清按本例目标回答并记录。未知受理结果先回读原任务，不重发。071、076、088及090～158的目标动作通过会话自然语言完成，135～158中明确安排的手动操作保留；不以直接API调用或原生编辑按钮代替被测自然语言动作。
4. 按真实页面业务、保存重开结果及实际文件验收；视频/声音需播放或听审。需求中的拟定内部字段、路由、错误码及算法不强加给页面；真实请求专项须先取得已实现入口。004对象引用/移除仍属明确需求，无入口也保留其失败检查点。
5. S0指本次修改前原稿，S1指本次成功修改后状态。先证实编辑成功，再撤销本次编辑；整组撤销须完整恢复，不能拆成反向修改冒充。除明确要求刷新恢复的场景外，撤销/重做在刷新前完成，不额外要求刷新后保留Redo。
6. 多组参数、不同账号/浏览器、正常/异常对照及恢复阶段分别核对；缺前置只阻塞依赖步骤。正式要求的业务缺失或结果错误按预期记录，文案整理不改变验收标准。
7. 用例表只维护设计；实际状态、缺陷和截图在独立执行登记及报告维护。自然语言专项不扩回已移出的计费/账单、后台协议或外部客户端授权范围；未公布的性能阈值不自定。
