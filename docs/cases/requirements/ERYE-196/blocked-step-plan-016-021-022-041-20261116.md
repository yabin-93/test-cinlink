日期：2026-11-16。适用016、021、022、041。按用户要求把阻塞拆到具体步骤，先完成可独立执行的准备，再验证正式业务目标。初版仅整理；用户要求重跑后已实际补跑，最新结果见[执行报告](results-stepwise-016-021-022-041-chrome-prod-20261116.md)：016 Passed，021/022/041 Blocked，各准备步骤分别保留。

## 执行规则

- 每一步记录目标工程、实际参数、完成证据、保存回读及下一步；部分完成保留检查点，不因后续阻塞重复上传、创建或发送已受理任务。
- 一个准备步骤只做一件事：先初始化，再添加对象，再核对关联；不把所有前置塞进一条复杂指令。独立且安全的准备可以继续，依赖缺失的步骤暂停并说明具体条件。
- 单项准备成功不等于整例通过。正式目标涉及关联随动、同组拒绝/回滚或一次撤销时，仍按原要求执行，不能用分别移动各轨、两次独立修改或多次撤销代替。
- 异常后先结束实际交互、回读当前保存状态，再决定是否继续未完成步骤。超时或“结果未知”不直接重发；不通过重复点击重试覆盖原失败。
- 界面与真实接口可观察内容作为依据；不要求先公布内部字段或开发接口。没有真实异常夹具时，标记对应分支未覆盖，不伪造关系、权限或素材ID。
- 各步骤可标完成/失败/阻塞/待执行，整例仍按覆盖范围汇总。仅步骤细化不改变旧执行结论；固定脚本均PLAN、路径为空。

## 041：正常基线与三个异常场景分开

不再要求不相关的整套B0，仅准备视频、一条有效字幕C1、一个正常图片水印W_IMG及有效替换图。固定配音/BGM不是本例必要前置。

| 步骤 | 具体操作 | 完成检查/后续处理 |
|---|---|---|
| 1 初始化 | 建立独立视频工程并保存 | 记录实际工程/视频范围 |
| 2 准备字幕 | 单独添加或绑定C1，记录原文、时间和样式，保存回读 | 字幕可明确定位和编辑 |
| 3 准备水印 | 单独上传有效图片并添加W_IMG，记录位置、大小、透明度和时段 | 页面与预览正常，保存重开不丢失 |
| 4 正常对照 | 一次同组替换为有效图片并改C1，核验两项成功；随后用独立同基线副本或经核验恢复基线 | 单项准备可以拆开，但“同组提交是否留半成品”的正式目标不能拆成两次修改 |
| 5 上传中分支 | 仅在本机测试浏览器内通过较大合法图片/网络限速观察真实上传中状态，记录当前真实可引用对象；在其仍上传中时提交替换水印+C1改文的一次同组请求 | 素材未就绪不能替换成功，也不能只改字幕；若UI完全禁止引用或发送，记录已覆盖的入口防护，复合请求分支仍未覆盖；不捏造临时ID |
| 6 上传失败分支 | 在独立基线中取得真实失败上传状态（本机上传中断后恢复网络），核验实际失败提示和可引用对象，再一次同组替换水印+C1改文 | 记录真实失败/不存在引用入口，不把“取消上传”或普通损坏图片直接当上传失败资产；没有可引用入口时不冒充已测后续回滚 |
| 7 无权限分支 | 由获准U2测试账号准备真实私有图片；记录U2可访问、U1无权访问，在U1用当前真实入口一次同组替换水印+C1改文 | 不新建共享授权，不使用随机ID或U1自己的图片代替；缺U2时只阻塞本分支，不阻止前两分支准备 |
| 8 各分支收尾 | 每个分支均核对错误、C1和有效水印，刷新重开并恢复本分支初始基线 | 无只改字幕/丢失水印等半成品；分支结论分别登记后再汇总整例 |

当前：三类异常图片的真实可引用状态均未核准，正常基线也应按本表逐项建立。用户提供的f178工程属于U1且未提供私有图片，不能代替U2对照。允许先执行已具备条件的分支；其余明确Blocked，不把一个分支的结果推广到另外两个。
