# 014编辑器故障的单步定位方式

2026-11-06用户要求分开一步步操作，定位具体卡点。此前自然素材指令同时描述视频裁头、独立旁白裁切、跨句字幕删词及全局对齐，属于完整联动验证，单凭它失败不能判断是哪一个基础编辑能力出错。

当前项目使用用户手动创建的[英文30S.mp4](user-project-baseline-20261106.md)。先按下面顺序做诊断；每次只发一个动作，回读实际保存结果后再决定下一步。失败时停在当前步骤记录，不继续叠加修改。

| 顺序 | 本轮只验证什么 | 独立检查点 |
|---|---|---|
| S1 | 单个视频片段裁掉开头4秒，不另做移动、字幕或旁白操作 | 视频实际源起点变为4秒，后续源内容保留；记录系统自然产生的关联变化；回读已保存版本，不能仅看任务done |
| S2 | 独立旁白音轨裁掉开头4秒 | 用真实音源裁切，保留原配音；不以改文字、变速或重新合成代替；其余对象不做独立编辑 |
| S3 | 一次只做一项字幕操作 | 重新选择当时仍存在的字幕，分别验证删除、文字或时间修改；不要沿用前一步已改变/删除的旧目标 |
| S4 | 如有需要再单独验证片段定位 | 检查明确对象的移动/时间对齐；不重复裁剪源内容 |
| 最终联动 | 基础项可用后再验证一句自然指令的自动同步 | 判断一次裁头能否自动同步声音和字幕；单项分别做成不能替代这一条组合验收 |

本次先发的S1提示词：

```text
先只做一步：在当前工程“英文30S.mp4”中裁掉视频片段开头4秒，暂时不移动片段，也不调整字幕和旁白。
```

后续提示词保持一个动作一句话；对象、素材时间及完整工程快照放在测试前置和证据中，不把整套内部参数、多个目标操作与实现要求堆进用户指令。仍需处理真实补槽，不能把提示词短作为拒绝澄清的理由。

最终联动可使用简短业务指令：“把当前视频开头4秒剪掉，字幕和旁白一起同步。”这条仍需按完整验收核对跨边界文字、真实音源及对齐，不能仅凭回复成功判通过。原ERYE196-014编号及业务要求保留，本页是故障诊断步骤，不增加新的正式需求用例编号。
