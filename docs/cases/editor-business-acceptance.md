# ERYE-196、206、210 业务验收口径

更新：2026-11-05。用户明确：三份用例按**页面业务或真实接口结果验收，不再根据需求文档中的接口设计验收**。本页是执行和维护这255条用例的统一规则；各需求正文保留需求来源，具体接口设计只作历史背景。

## 看什么结果

1. **页面业务**：能否完成明确操作；字幕文字/时间、片段顺序/时长、声音、水印、目标工程、导航、保存/撤销、任务及错误反馈是否正确。对保存结果刷新/重开验证；涉及视频或声音的效果应播放、听审或检查真实文件。
2. **真实接口**：使用页面实际发出的请求，或当前服务已实现且实际可访问的入口。记录真实请求方式/参数、响应及对应内容；将返回的工程、字幕、任务、文件与独立基线和用户指令核对。不能把接口恰好返回的值反推成期望，再自证通过。
3. 两种证据可按场景使用。界面“已完成”但字幕没改、文件打不开、作用到另一工程或重复收费，都不能算通过。纯导航也不能因没有返回某个拟定字段判失败。

## 不作为通过条件的实现选择

需求评论中的工具/路由名称、请求与响应字段、状态和错误码、ID分配方式、修订令牌、事件序号、数据库/投递事务、锁/租约、缓存键、内部时间编码、逐词分配算法及授权协议实现，不再要求与文档设计逐项一致。真实返回可作为定位证据，字段名字或实现不同本身不构成缺陷。

“一次撤销恢复本次复合修改”“重连不重复裁剪”“无权用户不能取得文件”等仍是要验证的业务效果；不据此规定底层必须调用一次接口、写几条历史记录或使用哪种锁。

## 如何准备和执行

- 每例只准备其检查的对象。只改字幕不要求同时制备BGM、配音和水印；需要验证三项组合时才准备完整组合基线。
- 选择目标按当前已有交互，或在指令中写全工程、素材、字幕起止时间及原文。没有对象引用标签不自动阻塞；多候选时按实际澄清继续。用户已排除的旧引用交互仍按本轮不适用处理。
- 参数上限、有效期、保存规则等先用实际已公开的页面说明/控件范围/真实接口规则；未明确则记录业务待确认，不套拟定数值。已确认的业务目标仍是独立标准，不能只因当前实现不同就放宽为任意成功。
- 接口专项先有真实请求再设计异常/重试数据，不按需求凭空拼端点、字段、scope或错误码。没有对应的内部设计接口，不作为产品失败或页面阻塞理由。
- 重复处理检查指同一原请求/已受理记录的重放或恢复；用户重新发送相同文字的新指令不自动视为同一次请求，不能仅按文本相同要求去重。
- 故障优先用当前可复现真实失败、断网/恢复、页面刷新/关闭和双标签操作。响应中断不等于服务端未保存，应重新打开核对。无法复现该故障分支就记未覆盖及原因；不要求研发先做专用内部故障点。
- 前端响应模拟只证明展示/恢复交互，不能证明服务端事务、计费或真实任务通过。本次不修改云端代码，不注入共享服务故障。

## 状态判定

| 情况 | 记录方式 |
|---|---|
| 已执行且实际业务符合完整预期 | Passed，附本次证据 |
| 已执行且确认范围内业务未达到，或真实结果错误 | 未通过/未实现，写清现象和证据，不以接口设计差异定缺陷 |
| 页面没有需求中拟定的内部接口/字段，业务已能完成 | 按业务实际结果判断，不因此Blocked |
| 纯接口设计场景没有任何对应实际入口，或明确不在本轮范围 | Not Applicable并说明边界；不把已确认必须交付的页面功能随意排除 |
| 需要真实素材/权限等必要条件而未准备 | 待准备/受阻，写具体缺口；不把整套不相关B0当全用例门槛 |
| 只改了用例或缺本轮实际证据 | Not Run/待复核，不因静态修改自动判通过 |
